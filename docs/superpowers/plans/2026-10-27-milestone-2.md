# Milestone 2 Implementation Plan

> Execute inline using superpowers:executing-plans; use a fresh final reviewer.
> **Goal:** Deliver the complete authenticated ticket workflow with separate backend and frontend PRs.
> **Architecture:** Preserve Domain/Application/Infrastructure boundaries. Application workflows coordinate domain aggregates and feature-specific stores; Infrastructure adapts Identity, EF, JWT and SMTP.
> **Tech Stack:** Existing Next.js 16/.NET 10/PostgreSQL stack; TanStack Query, React Hook Form, Zod and Cypress.
> **Spec:** docs/milestone-2.md

## Global constraints

- No token storage in localStorage; no attachment/search/jobs scope creep.
- No production seed accounts; no public secrets.
- API is authoritative for ownership, roles, status transitions and concurrency.
- Generated client is the only browser DTO contract.

## Review focus

- Another customer's GUID must not reveal ticket data or permit mutations.
- Internal notes must be absent from customer messages and audit events.
- Refresh reuse and logout/reset must revoke the session family.
- Wrong/stale versions must return conflict without overwriting work.
- Missing/invalid antiforgery tokens and privilege-bearing registration must be rejected.
