# Milestone 3 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement task-by-task with a fresh implementer and reviewer. Steps use checkboxes for progress.

**Goal:** Deliver secure ticket/reply attachments and Elasticsearch search with separate app PRs, tests and screenshots.
**Architecture:** Extend the existing modular monolith through Application ports and Infrastructure adapters. PostgreSQL authorizes all resources; the worker reconciles a public-content-only search projection.
**Tech Stack:** Existing .NET 10/PostgreSQL/Next.js stack, official AWS S3 SDK, Elasticsearch 8.19 HTTP API, SeaweedFS, Cypress.
**Spec:** docs/superpowers/specs/2026-10-28-milestone-3-design.md

## Global Constraints

- No merge; stack on unmerged M2 frontend. No additional worktree per existing ruling.
- No manually edited generated DTOs/migration designers. No localStorage tokens or secret logs.
- PDF/PNG/JPEG/UTF-8 text; 10 MiB/file, 10 files/ticket; private authorized downloads; current expectedVersion.
- Public-content search only; DB authorization/filter recheck; optional search with clear 503; no Hangfire/outbox until M4.

## Review Focus

- Stale ES ownership/filter projections cannot reveal ticket snippets, metadata or counts.
- Multipart validation cannot buffer unlimited files; conflicting concurrent uploads clean up stored objects.
- Internal-reply attachment names and download IDs never appear to customers.
- Account switches and mutation responses cannot move private attachments/search results across principals.
- Index loss and transient storage/search outages recover without losing authoritative tickets.

### Task 1: Backend attachments

Files: Domain/Tickets attachment entity/policy and aggregate methods; Application/Attachments contracts/workflow; Infrastructure/Attachments S3 adapter, EF metadata/model/migration; API/Features/Attachments endpoints and bounded multipart middleware; unit and integration tests.
Interfaces: GET/POST /api/v1/tickets/{id}/attachments, GET /api/v1/tickets/{id}/attachments/{attachmentId}/download. Upload multipart file, expectedVersion, optional messageId; response AttachmentView. List is role-filtered, download authorizes again. Keep existing TicketView contract stable; separate attachment query.

- [x] Write behavior tests and observe failures for ownership, validation, privacy, conflicts and cleanup.
- [x] Implement private S3 storage, application workflow, schema, routes and configuration with thin hosts.
- [x] Generate migration, inspect SQL, restore lockfiles; run attachment and existing backend tests, format and build.
- [x] Fresh review and fix issues; commit backend attachment slice.

### Task 2: Backend search and worker projection

Files: Application/Search contracts/workflow; Infrastructure/Search Elasticsearch adapter and DB hydration/projector; Worker/SearchProjectionService; API/Features/Search; tests; Compose and environment docs.
Interfaces: GET /api/v1/search/tickets accepts q, page, pageSize, status, priority, categoryId, agentId, from, to, sort. Return authorized TicketSearchPage with safe text snippets/highlight segments and bounded pagination. Worker executes idempotent reconciliation in DI scopes with cancellation.

- [x] Write failing behavior tests for full-text public replies, internal exclusion, filters, stale ownership and outages; real ES integration with optional native endpoint and default containers.
- [x] Implement bounded reconciliation, index bootstrap/mapping and HTTP search, DB validation, safe highlights, API and scoped registration.
