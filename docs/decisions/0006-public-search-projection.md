# 0006: Reconciled public search with database authorization

Status: accepted for Milestone 3.

Elasticsearch 8.19 is an optional derived public-content index accessed through built-in HttpClient and System.Text.Json, behind Application ports. Full-text fields contain ticket title, description, tags, number, and public replies. The explicit projection also carries ID, requester ID, ticket sequence, creation time, status, priority, category ID, and assigned agent ID. Strict mappings reject unexpected fields; internal notes and all attachment metadata/bytes are excluded for every role.

The separate worker runs an initial replay and periodic replays in fresh dependency-injection scopes. Each cycle captures the current maximum ticket number and reads keyset batches of at most 100 through that bound. Bulk index actions replace documents using ticket IDs, making repeated replay idempotent. Index bootstrap occurs each cycle, allowing a missing index to be rebuilt. Failure stops the current cycle, is logged without vendor details or secrets, and retries from the beginning after the configured interval. Cancellation propagates. No migrations run at host startup.

This is intentionally eventually consistent and has no durable checkpoint, transactional outbox, or Hangfire yet. Those belong to Milestone 4. Ticket deletion is not a product operation; stale derived documents are never trusted to authorize results. Full replay cost grows with the ticket set and should be replaced by durable change projection when scale requires it.

Search obtains a fixed maximum of 1000 IDs sorted by relevance/newest, with a requester filter for customers and requested status/priority/category/agent/date filters before the candidate window. PostgreSQL rechecks current ownership and status/priority/category/agent/inclusive UTC creation-day filters before counting and paging hydrated candidates. The API returns only the authorized window total, never Elasticsearch totals or source highlights. Public snippets are built from current PostgreSQL text and sent as `{ text, highlighted }` segments for safe React text/mark rendering. Dates use ISO YYYY-MM-DD; all roles search public content.

This bound limits query and hydration work, but means totals are exact only within the candidate window and stale filters/ownership can hide otherwise eligible tickets until replay. Relevance can also remain stale until replay. Search is disabled by default and failures yield generic 503 Problem Details. Core ticket operations and readiness depend on PostgreSQL independently of search.

Official HTTP API references: [bulk indexing](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/docs-bulk.html), [search](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/search-search.html), [multi-match](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/query-dsl-multi-match-query.html), and [index creation](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/indices-create-index.html).

The API normalizes single valid enum query names before Minimal API binding for search and ticket-list GET filters. This corrects a confirmed mismatch where generated camel-case enum values were rejected by case-sensitive query binding. Status/priority normalization applies only to those two collection routes, with sort normalization on search only. Typed Application DTOs and generated OpenAPI enums remain the contract. Invalid and duplicate enum filters return 400. Global and CSRF Problem Details now consistently use application/problem+json without changing status/body semantics.
